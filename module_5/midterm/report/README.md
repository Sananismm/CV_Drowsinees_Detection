# SG5 midterm evidence report

`SG5_Midterm_Report.pdf` is the eight-page, results-first technical report.
It uses actual frame crops, annotated-video outputs, larger comparison plots,
event timing zooms, captured console output and structured pipeline/action
diagrams. Essential assessment mapping, reproducibility and remaining checks
are retained without the earlier long narrative sections.

The PDF uses the verified full-run snapshot at commit `bf15c3b`, packaged in
`assets/evidence_bundle.json`. Later partial interactive runs do not alter its
totals. Console panels render actual captured CLI text for readability, not
invented application screenshots. Photos are crops from actual source frames,
labelled with recorded predictions rather than ground truth.
SVG diagrams in `assets/` are generated by the same source and are suitable for
GitHub display or reuse in a presentation.

To rebuild from the repository root, use a separate report environment:

```powershell
python -m venv .venv-report
.\.venv-report\Scripts\python.exe -m pip install -r module_5/midterm/report/requirements-report.txt
.\.venv-report\Scripts\python.exe module_5/midterm/tools/build_report.py --render-dir tmp/report_review --pr-url https://github.com/Sananismm/CV_Drowsinees_Detection/pull/21
```

Inspect every generated page image after changes. `tmp/report_review/` contains
QA images only; the final PDF and SVG assets are the report deliverables.
Large annotated videos and per-frame streams remain local and are regenerated
with the documented pipeline command; their small summaries/examples are
versioned. Physical Jetson and camera evidence must come from the actual device.

To regenerate the visual evidence, use the prepared vision environment:

```powershell
.\.venv\Scripts\python.exe module_5/midterm/tools/prepare_report_assets.py
```

This reads the pinned Git snapshots and the full Clip 02 cue streams, extracts
source-video crops and captures fresh SG4 demo output under ignored `tmp/`.
If the local Clip 02 cue streams are absent, first rerun that full video pipeline.
It performs no training, real-camera capture or model inference. Figure hashes
and provenance are recorded in `assets/evidence_manifest.json`.
Text hashes normalize Windows CRLF to LF so they also verify on Linux;
image hashes use exact bytes.
